The Meaning of VisoLink

以視覺化為入口，連結整合、感知與操作

VISO 對應 Visualize、Integrate、Sense、Operate 四個產品核心；Link 不是第五個獨立能力，而是讓四個核心形成完整技術鏈路的關鍵。

I — INTEGRATE

S — SENSE

感知

O — OPERATE

操作

Link 的技術含義：讓不同來源的工業資料連結到視覺化呈現，讓設備狀態、即時數據與趨勢連結到人的感知與判斷，再讓視覺化連結到實際監控與操作。

Design Principle

VisoLink 的技術核心，是在原始資料來源與最終 Display 之間，建立一層可治理、可重用的資料與視覺資產模型。

如果每張 Display 都直接保存自己的查詢、欄位解讀、計算與權限，系統規模一大就會形成新的資料孤島。VisoLink 將這些層次分開，使來源、語意、使用、呈現與治理可以獨立調整並保持一致。

來源不等於畫面DataSource 與 View 先整理資料契約，再交由 Display 使用。
資料不等於呈現DataBinding、Calculation 與 Symbol 分離資料語意與視覺表達。
可看圖不等於可取資料圖面授權與資料授權分開判斷。
可運行不等於可維運Cache、稽核、備份、狀態與授權是正式產品責任。
Family Architecture

資料從設備一路到畫面，回寫沿原路返回，備份中心在旁統一保障

設備 → Agent → DataGateway → VisoLink 是資料方向；回寫方向相反。已有資料庫或 Historian 時，VisoLink 直接連接，不經 DataGateway。

各自獨立運作：任何一個產品停機，不會讓其他產品失去自己的設定與資料。Agent 連不上 DataGateway 時先本機暫存；VisoLink 不使用 DataGateway 時照常以自己的連接器運作；備份中心停機只影響排程備份，各產品仍可在自己的管理畫面手動備份。

DataSource將關聯式、時序或工業歷史資料庫的連線差異集中封裝。來源端點或憑證變更不應要求逐張修改 Display。

DataBinding組織 Studio 使用入口、輸出欄位、權限與 Runtime Cache。可盤點哪些 Display 與 Symbol 依賴特定資料資產。
Calculation在不修改來源系統下建立條件、轉換及跨來源衍生指標。必須定義時間基準、缺值、型別與邊界情境。

DataSource 支援類型：關聯式資料庫 MySQL 8.0 以上（含 MariaDB 10.6 以上）、Oracle Database（19c 以上）、PostgreSQL、SQL Server；時序資料庫 InfluxDB（Flux、InfluxQL）；工業歷史資料庫 easyPI WebAPI、IIoTFab PIES 與 VisoLink DataGateway。VisoLink DataGateway 資料來源讀取歷史；DataGateway 的即時值與回寫另走後台「DataGateway 即時」，見下方整合點。

Integration Points

VisoLink 與 DataGateway 之間只有三條整合路徑

即時與歷史分開設定：即時與回寫走配對碼建立的專用連線，歷史走 DataSource。兩者都由 VisoLink Server 連到 DataGateway，使用者瀏覽器只連 VisoLink。

REALTIME

後台：DataGateway 即時配對碼即時連線

在 DataGateway 總覽複製 VisoLink 配對碼，貼到 VisoLink「即時來源」，即解析出 DataGateway 位址、讀取身分、回寫服務身分與憑證，不必交換管理員帳密或搬設定檔。

  • 即時 View 以 DataGateway 的 Tag 識別，Tag 改名或換來源畫面不必重設
  • DataGateway 重新產生配對碼，舊碼立即失效
  • 即時推送量可設定訂閱上限與節流間隔
HISTORY

後台：資料來源VisoLink DataGateway 資料來源

DataSource 類型「VisoLink DataGateway」讀取 DataGateway 保存的歷史與目前 Tag 資料，供趨勢、表格等歷史查詢使用；View 可選原始紀錄或內插模式。

  • 以 DataGateway 總覽提供的 WebAPI 位址與唯讀帳密連線，與配對碼分開設定
  • 歷史以 Tag 為準，Agent 離線或換來源仍查得到
  • 和其他 DataSource 一樣經過 View、DataBinding 與資料權限
WRITE-BACK

Runtime：回寫表單回寫路徑

Runtime 回寫表單送出設定值，經 VisoLink Server、DataGateway、Agent 寫入設備；DataGateway 以 Tag 為目標自動找到對應的 Agent 點，並記錄結果與設備讀回值。

  • 回寫走 Agent 連到 DataGateway 的既有連線，Agent 在其他網段也能回寫
  • 支援 Modbus TCP 與 OPC UA
① VisoLink 即時來源開啟「允許經由 VisoLink 回寫這個 DataGateway」。
② DataBinding 寫入權限與使用權限分開設定；預設拒絕，管理員也沒有自動例外。
③ DataGateway 可寫Tag 須可提交回寫，不可寫時顯示原因。
④ Agent 寫入安全規則連線開啟回寫，可寫 Tag 須指定寫入安全規則。

四道關卡缺一不可：任何一道未允許，畫面仍可讀取即時值，但無法回寫。

外部程式串接：VisoLink、DataGateway 與 Agent 都可在管理畫面建立 API Token（可設到期、可撤銷、只開放必要範圍），供備份中心等外部程式使用；備份中心登記受管主機時，填入在各產品畫面建立的 Token。

Runtime Query & Analysis

Runtime 的核心不是輪詢數值，而是維持一致的時間、權限與資料狀態

  1. 建立 Runtime ContextDisplay、目前使用者、顯示模式、即時／歷史範圍與刷新條件共同形成查詢情境。
  2. 解析 Display 依賴依 Symbol、DataBinding、Variable 與 Calculation 判斷需要的資料。
  3. 執行權限與 Cache 判斷確認資料使用權，並依 Binding 與 TTL Policy 決定共用或重新查詢。
  4. 統一時間查詢全畫面 Symbol、Quick Trend、Time Marker 與區間彙整使用相同時間基準。
  5. 呈現明確狀態值、時間、單位、載入、無資料、無權限與錯誤均需可辨識。

Operational Governance

維護、還原與保存都有明確規則，不靠人工記得

產品家族共用同一套維運語言：維護中就是全部暫停，還原就是整套停工，保存就是依政策執行。

VisoLinkDataGatewayAgent

運作中／維護中模式

維護中暫停資料讀取、回寫與設定修改，VisoLink Client 顯示維護畫面；Agent 維護中資料暫存在本機。切回運作中後自動恢復、補傳。

備份中心

還原時整套停工

開始還原前，備份中心把所有受管主機切到維護中，確認每台都連得上才開始；結束或失敗後切回原本的模式。備份是定時快照，還原回到備份當時的狀態。

備份中心

版本不同不允許還原

主機目前的產品版本必須與備份版本相同；請先把產品裝成相同版本再還原。授權不在備份內，換機後需為新機器重新申請並啟用授權。

DataGateway

未指定保存政策的 Tag 不保存

歷史依保存分類與規則保存，儲存前可試算；可指定哪些資料點使用保存額度。只保存需要的資料，容量可預期。

備份密碼：所有備份檔以備份密碼加密，備份中心只保存驗證資料、不保存密碼本身；遺失備份密碼就無法還原，導入時須指定保管責任人。

Deployment & Operations

自行部署的價值，不只是資料留在內網，而是企業能掌握整個服務生命週期

容器化解決服務組合問題；真正的可維運性還需要持久化、狀態、快取、備份、授權、稽核與變更流程。

各自以 Docker Compose 部署，放在最適合的位置

四個產品各有自己的 Docker Compose 與持久化資料，可以分別安裝、升級與停機；每個產品都提供 Windows 與 Linux 安裝程式與離線安裝包，安裝在已備妥 Docker 的主機上。Agent 設計精簡，裝在靠近設備、已備妥 Docker 的主機上取得資料；同一台主機也可安裝多個 Agent。

DataGateway、Agent、備份中心都有自己的本機管理員帳號，可獨立運作；DataGateway 也可使用 VisoLink 管理員帳號登入。

換機不必重設現場

以備份中心換機還原後，新機器帶回原機身分；DataGateway 換機後，Agent 不必改設定就會自動連回。

VisoLink 的服務組成

  • Docker Compose：組合使用者前台、應用服務、管理後台與相依資料服務。
  • PostgreSQL：保存設定、Display、資料資產、權限、語系與稽核等持久資料。
  • Volume：媒體、備份及必要金鑰需納入保存、權限與備援規劃。
  • Cache：管理 Server、連線、拓樸、Key、TTL Policy 與選擇性清除範圍。
  • System Status：從應用服務、執行環境、儲存與部署資訊辨識異常層級。
