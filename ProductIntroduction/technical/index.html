Design Principle

VisoLink 的技術核心，是在原始資料來源與最終 Display 之間，建立一層可治理、可重用的資料與視覺資產模型。

如果每張 Display 都直接保存自己的查詢、欄位解讀、計算與權限，系統規模一大就會形成新的資料孤島。VisoLink 將這些層次分開，使來源、語意、使用、呈現與治理可以獨立調整並保持一致。

來源不等於畫面DataSource 與 View 先整理資料契約，再交由 Display 使用。
資料不等於呈現DataBinding、Calculation 與 Symbol 分離資料語意與視覺表達。
可看圖不等於可取資料圖面授權與資料授權分開判斷。
可運行不等於可維運Cache、稽核、備份、狀態與授權是正式產品責任。

Data Asset Lifecycle

一筆資料進入 Display 以前，先經過五個可管理的資料層次

這條生命週期使資料來源異動、欄位語意、快取策略、使用權限與視覺呈現不必綁死在同一張畫面。

DataSource連線類型、端點、憑證、測試與啟停。
View查詢定義、來源選擇與可重用資料範圍。
Field Mapping名稱、型別、時間、單位與原始欄位對應。
DataBinding輸出欄位、使用權限、結果預覽與 Cache。
Display AssetVariable、Calculation、Symbol 與 Runtime 情境。
資料層次解決的技術問題變更影響
DataSource將關聯式、時序或工業資料服務的連線差異集中封裝。來源端點或憑證變更不應要求逐張修改 Display。
View限定可用資料範圍並建立相對穩定的查詢介面。Schema 變更可先在資料管理層檢查與預覽。
Field Mapping把原始欄位轉成設計者可理解的名稱、型別、時間與單位。降低 Studio 對來源實體結構的直接依賴。
DataBinding組織 Studio 使用入口、輸出欄位、權限與 Runtime Cache。可盤點哪些 Display 與 Symbol 依賴特定資料資產。
Calculation在不修改來源系統下建立條件、轉換及跨來源衍生指標。必須定義時間基準、缺值、型別與邊界情境。

相容性是設計規則的一部分：不同 Symbol 接受的 Binding、Field 或 Calculation 類型不同；設計者應從資料型別與資訊問題選擇元件，而不是只追求視覺豐富。

Runtime Query & Analysis

Runtime 的核心不是輪詢數值，而是維持一致的時間、權限與資料狀態

  1. 建立 Runtime ContextDisplay、目前使用者、顯示模式、即時／歷史範圍與刷新條件共同形成查詢情境。
  2. 解析 Display 依賴依 Symbol、DataBinding、Variable 與 Calculation 判斷需要的資料。
  3. 執行權限與 Cache 判斷確認資料使用權，並依 Binding 與 TTL Policy 決定共用或重新查詢。
  4. 統一時間查詢全畫面 Symbol、Quick Trend、Time Marker 與區間彙整使用相同時間基準。
  5. 呈現明確狀態值、時間、單位、載入、無資料、無權限與錯誤均需可辨識。

AGGREGATION

對選定期間取得加總、平均、最大、最小與筆數。

安全呈現原則：無資料、無權限、來源錯誤與真正的零值是四種不同狀態；Runtime 不應將它們合併成同一個視覺結果。

Security & Governance

圖面入口與資料內容採不同授權面向

授權不能只在使用者打開 Display 時檢查一次；Runtime 查詢資料時仍須依資料資產與使用者身分判斷。

Deployment & Operations

自行部署的價值，不只是資料留在內網，而是企業能掌握整個服務生命週期

容器化解決服務組合問題；真正的可維運性還需要持久化、狀態、快取、備份、授權、稽核與變更流程。

Users / Browser ↓ Client：Display Library / Studio / Runtime ↓ Server：Identity / Display / Query / Permission ↙ ↘ Industrial Data ← DataSource / Cache → PostgreSQL ↓ Admin：Governance / Audit / Backup / License
  • Docker Compose：組合使用者前台、應用服務、管理後台與相依資料服務。
  • PostgreSQL：保存設定、Display、資料資產、權限、語系與稽核等持久資料。
  • Volume：媒體、備份及必要金鑰需納入保存、權限與備援規劃。
  • Cache：管理 Server、連線、拓樸、Key、TTL Policy 與選擇性清除範圍。
  • System Status：從應用服務、執行環境、儲存與部署資訊辨識異常層級。
