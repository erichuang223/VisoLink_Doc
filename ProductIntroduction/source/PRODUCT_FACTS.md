# VisoLink 對外產品事實

- 文件角色：業務版與技術版產品介紹的共同事實來源
- 基準日期：2026-11-26
- 對應系統版本：VisoLink（VL）1.4.0-beta、VisoLink DataGateway（DG）與 DataGateway Agent 0.4.0-beta、VisoLink 備份中心（BackupCenter，BC）0.1.0
- 主要驗證來源：`OperationManual/`、`Training/`、各產品發行紀錄（CHANGELOG）

## 0. 產品家族

VisoLink 產品家族由四個可各自部署、各自運作的產品組成。客戶可以只用 VisoLink，也可以依需要加上 DataGateway、Agent 與備份中心。

| 產品 | 定位 | 一句話說明 |
|---|---|---|
| VisoLink（VL） | 工業資料視覺化平台（主軸） | 把既有資料變成可設計、可分析、可治理的監控畫面。 |
| VisoLink DataGateway（DG） | 設備資料中樞 | 集中管理 Tag，接收現場資料，依保存政策保存歷史，提供即時、歷史查詢與設備回寫。 |
| DataGateway Agent（Agent） | 現場資料取得 | 部署在設備旁，以 Modbus TCP、OPC UA 讀取設備資料推送給 DG，並執行回寫；設計精簡，可在小型設備上執行。 |
| VisoLink 備份中心（BackupCenter，BC） | 中央備份與還原 | 統一排程備份 VL、DG、Agent，並可還原到原機或在新機器上換機還原。 |

搭配原則（對外必須一致）：

- **各自獨立運作**：VisoLink 不需要 DataGateway 也能使用，直接以自己的連接器讀取既有資料庫與時序資料庫；DataGateway 也能單獨運作。
- **整合點明確**：VisoLink 以「DataGateway 資料來源」讀取 DG 的即時值與歷史，並透過 DG 回寫設備；連線以 DG 提供的配對碼完成。
- **資料流**：設備 → Agent → DataGateway → VisoLink 畫面；回寫方向相反，由 VisoLink 操作表單經 DG、Agent 寫回設備。
- **產品自己就能備份**：VL、DG 都能在自己的管理畫面手動備份與還原；備份中心再加上中央管理、排程與換機還原。
- **備份是定時快照**：還原回到備份當時的狀態；還原期間所有受管主機切換為「維護中」，結束後恢復運作。
- 對外文件不描述廠商端的授權發行系統；只描述客戶端可見的授權啟用、離線啟用與用量畫面。

## 1. 產品定位（VisoLink）

VisoLink 是可自行部署的工業資料視覺化平台，將既有資料來源連接、資料整理與綁定、衍生計算、自由畫布設計、Runtime 監看分析及企業治理串成同一個工作流程。

### 品牌命名意義

VisoLink 的 **VISO** 代表四個產品核心：

| 字母 | 產品核心 | 中文意義 | 對應價值 |
|---|---|---|---|
| V | Visualize | 視覺化 | 將設備、環境與營運資料轉化為直觀、易懂的資訊。 |
| I | Integrate | 整合 | 串聯不同系統、設備與資料來源，減少資訊孤島。 |
| S | Sense | 感知 | 即時掌握現場狀態與變化，協助人員判斷。 |
| O | Operate | 操作 | 將洞察轉化為監控、操作與改善行動。 |

**Link 不是第五個獨立能力，而是串聯 VISO 四個核心的關鍵：**

- Visualize × Link × Integrate：讓不同來源的工業資料，連結到視覺化呈現。
- Visualize × Link × Sense：讓設備狀態、即時數據與趨勢，連結到人的感知與判斷。
- Visualize × Link × Operate：讓視覺化不只是「看見」，更能連結到實際的監控與操作。

官方命名解釋為：「以視覺化為入口，連結整合、感知與操作。」品牌主張為：「VisoLink — 讓視覺化，連結資料整合、現場感知與實際操作。」

對外介紹時必須保留的核心論述：

- VisoLink 解決的是工業資料視覺化的「最後一哩」，不是取代客戶既有的 PLC、DCS、Historian、MES 或資料庫投資。
- 根本問題是現場知識與畫面控制權分離，使日常改善反覆變成專案。
- 產品價值同時來自兩端：讓具權限的現場設計者能自主交付，也讓企業保留資料、權限、版本、稽核、備份及維運治理。
- 每次交付應累積成可重用的 DataSource、View、DataBinding、Calculation、Display、Symbol 與操作知識，而不是只產出一張畫面。
- 詳細的業務與技術論述順序見 `CONTENT_STRATEGY.md`。

主要工作區：

- Display Library：管理 Folder、Display、縮圖與圖面權限。
- Studio：設計 Display、加入 Symbol、綁定資料、建立 Variable 與 Calculation。
- Runtime：即時與歷史監看、全域時間情境、Quick Trend、Time Marker 與時間範圍彙整。
- Administration：管理資料、人員、權限、語系、授權、稽核、備份、API Token、系統狀態與 Cache。

## 2. 對外可描述的核心能力

### 資料與整合

- 建立及測試 DataSource 連線；支援 InfluxDB、PostgreSQL、MySQL、MariaDB、SQL Server、Oracle Database（19c 以上）與 VisoLink DataGateway。
- 關聯式資料庫提供引導式設定、標準查詢、時間區間彙整、Tag Pivot 與進階 SQL；資料查詢以唯讀方式執行。
- DataGateway 資料來源以配對碼連線，可讀取設備目前值與歷史，並設定即時讀取與回寫權限。
- 建立 View、欄位映射與結果預覽。
- 以 DataBinding 將來源整理成可供 Studio 使用的資料資產。
- Data Browser 支援依分類瀏覽、搜尋及拖曳套用資料。
- Variable 與 Calculation 支援資料轉換、條件邏輯及跨來源衍生指標。

### 視覺設計

- 自由畫布、畫布設定、物件編輯、排列、圖層、復原與重做。
- Symbol 類型涵蓋圖形、文字、圖片、iFrame、數值、趨勢、表格、狀態、Gauge、Bar、Pie、Sankey、Chord 與 Progress 等用途。
- 圖庫由伺服器統一提供，含智慧圖形（彎管、三通、箭頭、PID 管道等），拖曳控制點改變形狀、端點自動接上設備管口；管理員可在後台上傳 SVG 與製作智慧圖形。
- Display 可儲存、預覽、複製、分類與管理權限；可從 Display 樣本建立，可套用共用底板（Logo、標題、頁尾）。
- Symbol 樣本可複製使用，或以「繼承」方式讓樣本修改後所有使用處一起更新。
- 同一張 Display 可另外製作 RWD 版面，手機與平板開啟時自動改用。
- 多張 Display 可匯出成一個檔案，到另一套 VisoLink 匯入，資料依名稱自動對應；可一次替換整張 Display 使用的 DataBinding。
- 監控元件可設定設備回寫表單（Modbus TCP、OPC UA，經 DataGateway），Runtime 直接開啟表單送出設定值並顯示結果。

### Runtime 監看與分析

- 支援即時與歷史時間情境、全域時間 Filter 及互動式時間窗。
- Quick Trend 可選擇多個資料點進行趨勢比較。
- Time Marker 可建立、保留、拖曳、排序及比較時間點。
- 時間範圍彙整支援加總、平均、最大、最小與筆數等分析。
- Runtime 顯示載入中、無資料、無權限與錯誤等狀態，避免誤認為正常值。
- 可依管理員設定的班別等時間條件一鍵切換查詢區間。
- Runtime 網址可帶參數（隱藏工具列、縮放、查詢時間），方便嵌入其他系統。
- 登入可勾選「保存登入」；同一帳號可在多台裝置同時登入。

### 治理與維運

- 圖面權限與資料權限分開管理。
- 後台涵蓋 Users、Groups、Roles、DataSource、DataBindings、Data Permissions、Folders、Media Library、Localization、License、Audit Logs、Backup & Restore、API Token、System Settings 與 Cache Management。
- 敏感連線資訊、身分驗證、稽核與備份屬於企業治理能力的一部分。
- Cache 可管理節點、連線、狀態、Key、TTL Policy 與清除範圍，支援查詢共用及負荷分流情境。
- 使用者管理可預覽有效權限：一次看到使用者對 Display、Folder、DataBinding 及系統功能的最終存取結果。
- 運作中／維護中模式：維護中暫停資料讀取、回寫與設定修改，Client 顯示維護畫面，切回後自動恢復。
- 管理畫面可手動備份與還原；也可交由 VisoLink 備份中心統一排程。

### 部署

- 使用者前台、應用服務、管理後台與持久化資料分工部署。
- 支援以 Docker Compose 在企業環境自行部署及維運；提供 Windows 與 Linux 安裝程式。
- PostgreSQL 保存畫面資產、設定、權限及稽核等持久資料。

## 2A. DataGateway 與 Agent 可描述的能力

### DataGateway（DG）

- **Tag 管理**：Tag 屬於 DG，可單獨建立、改名、更換或移除寫入來源，Tag 與歷史不受影響；Agent 新增的點自動建立對應 Tag。每個 Tag 顯示來源狀態（正常、來源離線、來源停用、無來源、型別不符）。
- **歷史保存**：依保存分類與規則保存（完整保存、變更時保存、趨勢壓縮、定期取樣）；沒有指定保存政策的 Tag 不保存。保存規則可在儲存前試算；可指定哪些資料點使用保存額度。
- **即時與歷史查詢**：即時值依來源檢視並標示品質與是否過期；歷史查詢可多選 Tag，查原始紀錄或指定間隔插值，以趨勢圖與表格檢視。歷史以 Tag 為準，Agent 離線或更換來源仍查得到。
- **設備回寫**：以 Tag 為目標，DG 自動找到對應的 Agent 點，支援 Modbus TCP 與 OPC UA；每筆回寫記錄結果與設備讀回值。
- **Agent 管理**：核准、拒絕或解除 Agent 註冊；DG 重建後 Agent 可重新申請並補傳資料。
- **維運**：服務總覽與資料流程圖、資料流日誌、快取管理、歷史資料管理、系統設定中心（調整前預覽影響、可還原上次設定）、運作中／維護中總開關、手動備份與還原（設定與歷史資料，備份檔加密）。
- **登入**：可使用 VisoLink 管理員帳號登入，也可使用 DG 本機管理員帳號獨立運作。
- **與 VisoLink 整合**：首頁提供 VisoLink 配對碼，貼到 VisoLink 即完成即時讀取與回寫連線；可重新產生配對碼使舊碼失效。

### DataGateway Agent

- 支援多連線 Modbus TCP 與 OPC UA，依掃描群組讀取資料點並直接推送給 DG。
- DG 連不上時才把資料暫存在本機，恢復後自動補傳；暫存保留天數與容量上限可調整，可查看與清理暫存。
- 執行 DG 轉來的回寫；回寫走 Agent 連到 DG 的既有連線，Agent 在其他網段也能回寫。
- 設計精簡：只做資料取得、推送、接收與回寫，不做複雜運算，可在小型設備上執行。
- 可在 Agent 網頁設定 DG 連線與信任憑證、申請或解除註冊；維護中時資料暫存在本機，切回運作中後補傳。

## 2B. 備份中心（BackupCenter）可描述的能力

- **受管主機**：登記 VL、DG、Agent，定期檢查連線與版本。
- **存放位置**：本機資料夾、SMB、NFS、FTP、FTPS、SFTP；逐步測試連線與容量。
- **備份**：手動備份與排程（多種頻率、完整／快速設定／自訂內容），依保留份數自動清理；同一台主機一次只做一個工作，排隊原因可見。
- **加密**：備份檔以備份密碼加密，備份中心只保存驗證資料、不保存密碼本身；遺失備份密碼就無法還原。
- **還原**：原機還原、換機還原、局部還原與衝突策略；還原期間所有受管主機切到維護中，結束後切回；系統版本不同時不允許還原。換機後 Agent 不必改設定就會自動連回。
- **時序資料**：DG 內建 TimescaleDB 的完整／差異備份；InfluxDB v1／v2 備份與還原。
- **自身設定**：備份中心的主機、存放位置、排程等設定同步到存放位置，新機器可從存放位置還原。
- **登入**：單一組本機管理員帳號；初始帳密第一次登入強制修改，連續登入失敗會暫時鎖定。

## 4. 狀態與措辭規則

對外描述功能時使用以下狀態：

| 狀態 | 定義 | 對外用語 |
|---|---|---|
| Released | 正式介面存在，操作手冊已有正式內容 | 支援、提供、可使用 |
| Environment Validation | 功能存在，但客戶環境的資料生命週期或權限結果仍需依政策驗證 | 支援，導入時需確認政策 |
| Preview | 已可展示，但尚未完成正式驗收 | 預覽、試用 |
| Roadmap | 尚未作為正式功能交付 | 規劃中，不寫成現有能力 |

系統的預發行版（例如 VL 1.4.0-beta、DG 0.4.0-beta）中已具備正式介面的功能，以「支援」描述，並在文件註明對應的系統版本；系統正式版發行、內容不變時，只更新文件的對應版本。

目前需在客戶正式環境再次驗證的事項：

- Folder 刪除時內含 Display 的處理規則。
- Display 刪除後的結果與復原政策。
- Folder 與 Display 授權的繼承、覆寫及優先順序。
- 不同角色、群組及帳號組合下的實際授權結果。

## 5. 禁止直接使用的聲明

- 「所有功能均已完成」：改為逐項狀態與基準日期。
- 「無限制擴充」：改為可依架構與容量規劃擴充。
- 「完全不需要 IT」：Studio 降低日常畫面變更依賴，治理與資料仍由適當角色負責。
- 未經版本驗證的精確數量、效能數字、節省比例或競品結論。
