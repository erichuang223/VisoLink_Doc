# VisoLink 產品介紹內容主軸

## 1. 共同核心主張

VisoLink 不是另一套只負責顯示資料的 Dashboard，也不是把每一張監控畫面繼續當成一次性客製專案。它把工業資料視覺化的「最後一哩」建立成可持續使用的平台能力：讓懂現場的人能快速把資料轉成資訊畫面，同時保留企業對資料、權限、版本、稽核、部署與維運的治理能力。

產品介紹應在核心能力之前交代品牌命名：VISO 代表 Visualize、Integrate、Sense、Operate（視覺化、整合、感知、操作）；Link 不是第五個獨立能力，而是串聯四個核心的關鍵。論述必須以 Visualize 為入口，分別連結 Integrate、Sense 與 Operate，並回到「讓視覺化，連結資料整合、現場感知與實際操作」的產品工作流程。

整體論述必須維持以下因果鏈：

```text
企業已有大量資料投資
→ 資料仍分散在不同系統與語意中
→ 畫面需求依賴少數技術資源與個別專案
→ 交付慢、反覆溝通、成果難重用
→ VisoLink 將連接、整理、計算、設計、分析、治理變成同一平台流程
→ 現場取得調整能力，企業仍保有治理
→ 每次交付累積成可重用的資料與視覺資產
```

## 2. 業務版核心論述

### 主命題

把監控畫面的每一次需求，從「重新發起一個專案」，轉成「在既有治理下持續改善的日常能力」。

### 必須回答

1. 客戶真正付出的不只是軟體費，而是等待、溝通、反覆修改與機會成本。
2. 根本問題是現場知識與畫面控制權分離，不是企業沒有資料。
3. VisoLink 同時提供自主性與治理，不要求在兩者之間二選一。
4. 產品差異不只是一組功能，而是完整的資料到決策工作流。
5. 導入價值要透過真實 PoC 的時間、工時、需求往返與重用率驗證。

### 證據順序

客戶問題 → 結構成因 → 平台解法 → 六段工作流 → 產品能力 → 治理與規模 → 商業效益 → PoC。

## 3. 技術版核心論述

### 主命題

VisoLink 在原始資料來源與最終 Display 之間建立一層可治理、可重用的資料與視覺資產模型，並以統一時間情境、雙層權限及可維運部署支撐 Runtime。

### 必須回答

1. 原始資料如何經過 DataSource、View、Field Mapping、DataBinding 進入 Studio。
2. Variable、Calculation、Symbol 與 Display 如何形成可重用資產。
3. Runtime 如何讓全畫面與分析工具共享時間情境。
4. 圖面權限與資料權限如何分工，無資料、無權限與錯誤如何安全呈現。
5. Cache、PostgreSQL、備份、稽核、授權與系統狀態如何支援維運。
6. 哪些是正式能力，哪些必須依客戶環境驗證。

### 證據順序

技術目標 → 邏輯架構 → 資料生命週期 → Studio 資產模型 → Runtime 查詢與分析 → 安全治理 → 部署維運 → 功能範圍與驗證邊界。

## 4. 文件分工

- 產品介紹：說明「為什麼、是什麼、如何構成、產生什麼價值」。
- 操作手冊：說明「在哪裡、怎麼操作、成功結果與注意事項」。
- 教育訓練：說明「不同角色如何學會、練習、驗收與交接」。

產品介紹可以引用售後文件作為功能證據，但不能退化成操作步驟摘要。
