# 從製造結果到製造過程：時序資料與交易資料完整教學

## 教材定位

本教材以製造工廠為背景，透過化工批次製造與設備維護案例，說明交易資料、時序資料及統計彙總資料的差異、特性與應用方式。

完成本課程後，學員將能夠：

1. 分辨交易資料、時序資料與統計彙總資料。
2. 判斷不同問題應使用哪一類資料。
3. 理解時序資料在製程、能源、設備與品質分析中的價值。
4. 理解交易資料在工單、物料、庫存、檢驗與管理作業中的角色。
5. 知道如何利用工單、批次、設備與時間區間連接兩類資料。
6. 以正確的時間範圍、資料粒度與統計方法設計時序查詢。

---

# 第一章　從一批產品開始認識工廠資料

## 1.1 情境故事

2026 年 8 月 17 日上午，化工廠準備使用 R-101 反應槽生產一批 Resin-A 樹脂。

08:00，操作人員依照工單開始投料；08:20，攪拌機與蒸汽系統開始運轉；09:00，物料進入主要反應階段；11:00，反應完成。這次生產共投入 1,000 kg 原料，完成 950 kg 成品，經品質檢驗後判定合格並辦理入庫。

對管理人員而言，這次生產可以描述為：

> B20260817001 批次使用 R-101 反應槽生產 Resin-A，08:00 開始、11:00 完成，投入 1,000 kg、產出 950 kg，檢驗結果合格。

對製程工程師而言，同一段生產還包含另一組重要資訊：

> 從投料到反應完成的三個小時內，溫度如何升高、壓力如何變化、攪拌轉速是否穩定、蒸汽閥門開度如何調整，以及這些變化是否符合標準製程。

兩段描述都在說明同一批生產，但它們記錄的是不同層面的事實：

- 第一段描述生產任務及其結果。
- 第二段描述生產過程中的連續變化。

前者主要由交易資料回答，後者主要由時序資料回答。

## 1.2 一句話理解兩種資料

> 交易資料告訴我們「完成了什麼」；時序資料告訴我們「過程如何發生」。

這兩種資料並不是互相取代的關係，而是從不同角度描述工廠營運。當兩者正確連接後，才能同時看見製造結果與形成結果的過程。

# 第二章　什麼是交易資料

## 2.1 基本定義

交易資料記錄具有業務意義、可被確認、追蹤、簽核或結算的事件與狀態。

工廠常見的交易資料包括：

- 生產工單建立、開工與完工
- 批次生產紀錄
- 原料領料、退料與投料
- 成品入庫與庫存異動
- 品質檢驗、判定與放行
- 設備報修、派工與完修
- 交接班與人員簽核
- 採購、銷售及成本結算

時間在交易資料中通常是描述事件的重要欄位。例如工單可能同時具有建立時間、預計開始時間、實際開工時間及實際完工時間。資料的核心仍是那一筆具有業務意義的紀錄。

## 2.2 批次生產交易資料範例

```csv
BatchNo,WorkOrder,Product,Equipment,StartTime,EndTime,InputKg,OutputKg,Result
B20260817001,WO20260817015,Resin-A,R-101,2026-08-17 08:00:00,2026-08-17 11:00:00,1000,950,Pass
B20260817002,WO20260817016,Resin-B,R-102,2026-08-17 09:10:00,2026-08-17 12:40:00,1200,1135,Pass
B20260817003,WO20260817017,Resin-A,R-101,2026-08-17 13:20:00,2026-08-17 16:35:00,1000,936,Hold
```

這份資料可以回答：

- 哪一張工單生產哪一項產品？
- 使用哪一台設備？
- 何時開工及完工？
- 投入與產出數量是多少？
- 生產時間多長？
- 目前檢驗結果為何？
- 哪些批次仍在待判定狀態？

## 2.3 交易資料擅長處理的問題

交易資料特別適合回答可列舉、可追蹤及可結算的業務問題，例如：

- 今天完成多少張工單？
- 本月各產品的產量是多少？
- 哪些原料已經領用？
- 哪些批次尚未檢驗或放行？
- 成品庫存還有多少？
- 哪一張維修單由哪一位人員處理？
- 哪些批次需要追溯或重新檢驗？

## 2.4 同一數字可能代表不同業務事實

一批產品完成後，系統中可能同時出現以下數量：

```csv
Source,QuantityKg,Meaning
FlowMeter,952.7,儀表依流量累積估算的數量
OperatorConfirmation,951,現場人員確認的完成數量
WarehouseReceipt,950,倉庫實際驗收入庫的數量
```

三個數字的用途不同：

- 儀表值適合觀察製程及物料流動。
- 現場確認值代表生產作業完成時的認定。
- 入庫值代表倉庫驗收後可納入庫存帳的數量。

因此，選擇資料以前應先確認問題所指的是量測事實、生產事實，還是庫存事實。

## 本章重點

> 交易資料的價值，在於保存可確認、可追蹤、可簽核與可結算的業務事實。

# 第三章　什麼是時序資料

## 3.1 基本定義

時序資料是依照時間順序，持續記錄某個對象的量測值、狀態或變化。

製造現場常見的時序資料包括：

- 溫度、壓力、流量及液位
- 馬達電流、轉速及振動
- 閥門開度與設備運轉狀態
- 燃氣、蒸汽、用電及壓縮空氣
- 外氣溫度、濕度與環境監測值
- 控制設定值與實際值

每一筆時序資料至少需要回答：

1. 什麼時間？
2. 測量或記錄什麼？
3. 當時的值是多少？

在工業應用中，通常還會包含設備、單位及資料品質等資訊。

## 3.2 一般時序資料結構

```csv
Timestamp,Equipment,TagName,Value,Unit,Quality
2026-08-17 08:00:00,R-101,Temperature,28.1,C,Good
2026-08-17 08:00:00,R-101,Pressure,1.02,bar,Good
2026-08-17 08:00:00,R-101,AgitatorSpeed,0,rpm,Good
```

各欄位的意義如下：

| 欄位 | 說明 |
|---|---|
| Timestamp | 數值所代表的時間 |
| Equipment | 資料所屬設備 |
| TagName | 測點或訊號名稱 |
| Value | 量測值或狀態值 |
| Unit | 工程單位 |
| Quality | 資料品質標記 |

## 3.3 化工反應過程資料範例

為了方便閱讀，下列範例將同一時間的多個測點展開成不同欄位：

```csv
Timestamp,Equipment,BatchNo,TemperatureC,PressureBar,AgitatorRPM,SteamValvePct
2026-08-17 08:00:00,R-101,B20260817001,28.1,1.02,0,0
2026-08-17 08:01:00,R-101,B20260817001,28.4,1.02,80,0
2026-08-17 08:02:00,R-101,B20260817001,29.2,1.03,80,25
2026-08-17 08:03:00,R-101,B20260817001,31.8,1.05,80,40
2026-08-17 08:04:00,R-101,B20260817001,35.6,1.08,80,45
2026-08-17 08:05:00,R-101,B20260817001,39.9,1.12,80,45
2026-08-17 08:06:00,R-101,B20260817001,44.3,1.16,80,42
2026-08-17 08:07:00,R-101,B20260817001,48.0,1.20,80,38
```

這份資料可以回答：

- 反應槽溫度如何隨時間上升？
- 蒸汽閥門開啟後，溫度多久開始產生明顯變化？
- 壓力是否隨溫度同步升高？
- 攪拌機在製程期間是否維持運轉？
- 某一時刻的設備狀態是什麼？
- 過程中最高溫度及最大壓力是多少？

## 3.4 採樣頻率與資料量

時序資料會依設定頻率持續產生。若一個測點每秒記錄一次：

- 每分鐘產生 60 筆
- 每小時產生 3,600 筆
- 每天產生 86,400 筆

如果工廠有 1,000 個測點，資料量便會快速累積。因此時序系統通常需要支援依時間區間查詢、彙總、降採樣及保存策略。

## 本章重點

> 時序資料的重點不是單獨的一個數值，而是數值依時間排列後所呈現的變化、趨勢與關係。

# 第四章　交易資料與時序資料的差異

## 4.1 資料特性比較

| 比較項目 | 交易資料 | 時序資料 |
|---|---|---|
| 主要描述 | 業務事件與作業結果 | 狀態與量測值隨時間的變化 |
| 常見來源 | ERP、MES、WMS、LIMS、CMMS | PLC、SCADA、DCS、儀表、Historian |
| 典型識別 | 工單號、批號、單據號 | 時間、設備、測點名稱 |
| 產生方式 | 作業發生、確認或簽核時建立 | 依採樣或變化規則持續產生 |
| 資料頻率 | 依事件發生 | 毫秒、秒、分鐘或依值變化 |
| 常見查詢 | 筆數、清單、狀態、合計、追蹤 | 趨勢、區間、極值、波動、持續時間 |
| 主要價值 | 管理、追溯、結算、稽核 | 監控、診斷、預警、最佳化 |

## 4.2 從問題選擇資料

| 想回答的問題 | 主要資料來源 |
|---|---|
| 這一批生產了多少成品？ | 交易資料 |
| 生產過程中的最高溫度是多少？ | 時序資料 |
| 這一批是否判定合格？ | 檢驗交易資料 |
| 不合格批次的溫度如何變化？ | 交易資料＋時序資料 |
| 本月完成多少張工單？ | 交易資料 |
| 哪一台設備經常出現瞬間壓力波動？ | 時序資料 |
| 哪個產品的單位能源消耗最高？ | 交易資料＋時序資料 |
| 目前庫存還有多少？ | 交易資料 |
| 蒸汽使用量何時突然增加？ | 時序資料 |
| 哪些批次受到蒸汽異常影響？ | 交易資料＋時序資料 |

## 4.3 課堂判斷練習

請判斷下列問題主要需要哪一類資料：

1. 昨天夜班完成多少產量？
2. 昨天夜班哪一個時段用電量最高？
3. 哪些產品已完成品質放行？
4. 反應槽在保溫階段是否出現溫度震盪？
5. 哪張工單的平均蒸汽單耗最高？

參考答案：

1. 交易資料；需要班別與完工產量。
2. 時序資料；需要各時間區間的用電量或需量。
3. 交易資料；需要檢驗與放行狀態。
4. 時序資料；需要保溫期間的連續溫度。
5. 兩者整合；交易資料提供工單與產量，時序資料提供蒸汽累積用量。

# 第五章　原始資料、統計資料與交易資料

## 5.1 三者代表不同層次

除了交易資料與時序資料，工廠報表中還經常使用統計彙總資料。

- 原始時序資料：保存各個時間點的量測值。
- 統計彙總資料：依指定時間區間及計算方法產生摘要。
- 交易資料：保存具有業務意義的事件、結果與認定。

## 5.2 原始值與平均值範例

原始量測資料：

```csv
Timestamp,TemperatureC
2026-08-17 08:00:00,80.1
2026-08-17 08:00:01,80.5
2026-08-17 08:00:02,95.2
2026-08-17 08:00:03,80.4
```

彙總成一分鐘平均值：

```csv
Minute,AverageTemperatureC
2026-08-17 08:00:00,84.05
```

平均值適合呈現這一分鐘的整體水準，但瞬間出現的 95.2°C 不再直接顯示。因此，選擇平均值、最大值、最小值或原始值，取決於分析目的。

## 5.3 同一段資料的不同統計結果

```csv
Period,AverageC,MinimumC,MaximumC,LastC
2026-08-17 08:00,84.05,80.1,95.2,80.4
```

各統計值回答不同問題：

- Average：這段時間的整體平均水準。
- Minimum：這段時間出現的最低值。
- Maximum：這段時間出現的最高值。
- Last：區間結束前最後取得的數值。

因此，報表中的一個數字應同時說明時間區間、計算方法與資料來源。

## 5.4 累積值與瞬時值

能源與流量資料尤其需要區分：

- 瞬時流量：當下每小時的流量，例如 120 Nm³/h。
- 累積流量：儀表從某個起點累積的總量，例如 58,320 Nm³。
- 區間用量：區間結束累積值減去區間開始累積值。

```text
區間用量 = EndTotalizer - StartTotalizer
```

若將瞬時流量直接相加，或把累積值當成當期用量，便會得到不同含義的結果。因此計算前應先確認測點代表的物理意義。

## 本章重點

> 統計資料是依規則從資料中產生的摘要。閱讀統計結果時，要同時確認統計區間、計算方式與原始資料粒度。

# 第六章　時間是時序查詢的核心

## 6.1 一次完整的時序查詢

一個完整的時序查詢通常需要四項條件：

1. 對象：查哪一台設備或哪一個測點？
2. 時間：查詢的開始與結束時間為何？
3. 粒度：需要原始值、每分鐘、每小時或每日資料？
4. 方法：需要平均、最大、最小、總和、最後值或其他計算？

例如：

> 查詢 R-101 反應槽於 2026-08-17 08:00 至 11:00 的溫度，每分鐘計算平均值及最大值。

這個問題同時指定了設備、時間範圍、資料粒度與統計方法，因此可以得到清楚且可解釋的結果。

## 6.2 為什麼需要時間範圍

時序資料會持續增加。時間範圍不只是系統查詢條件，也代表分析情境。

例如「R-101 的平均溫度」需要先確認是：

- 最近一小時
- 今天早班
- 某一個生產批次
- 本月所有批次
- 設備啟動後至目前

不同時間區間會形成不同結果，也代表不同管理意義。

## 6.3 時間範圍與資料粒度

| 使用情境 | 常見查詢期間 | 建議粒度 |
|---|---|---|
| 瞬間設備異常 | 數秒至數分鐘 | 毫秒或秒 |
| 製程趨勢分析 | 數小時至一批次 | 秒或分鐘 |
| 班別能源分析 | 8 至 12 小時 | 分鐘或小時 |
| 月度管理報表 | 一個月 | 小時或日 |
| 年度能源趨勢 | 一年 | 日或月 |

查詢期間越長，通常越需要適當彙總。例如呈現一年的能源趨勢時，使用每日或每月資料通常比載入每秒原始值更符合閱讀目的。

## 6.4 資料時間與寫入時間

工業資料可能包含兩種時間：

- Event Time：設備實際量測或事件發生的時間。
- Ingestion Time：資料寫入平台或資料庫的時間。

當網路中斷後重新補傳資料時，兩者可能不同。製程分析通常應以事件發生時間為主；系統傳輸監控則可能需要觀察寫入時間與延遲。

## 6.5 時間同步

若 PLC、SCADA、資料平台及 MES 的系統時間不一致，即使每一套系統各自保存完整資料，也可能無法正確還原同一段製程。因此工廠資料整合通常需要：

- 統一時區
- 設備與伺服器時間同步
- 明確保存時間格式
- 處理延遲上傳與補傳資料
- 定義區間邊界是否包含開始及結束時間

# 第七章　時序資料能看見哪些製造價值

## 7.1 看見完整的變化過程

交易資料可以記錄設備於 08:00 開機、11:00 停機；時序資料則可以呈現三個小時內的溫度、壓力、電流、轉速及流量變化。

藉由時間順序，可以觀察：

- 上升與下降速度
- 穩定程度
- 週期性波動
- 瞬間尖峰
- 長時間偏移
- 設備狀態切換
- 製程階段轉換

## 7.2 找出異常發生時間與前兆

設備在 10:35 停機，維修紀錄可以說明停機原因與處理結果；時序資料可以向前追查異常如何形成。

```csv
Timestamp,Equipment,VibrationMMs,BearingTempC,MotorCurrentA,RunStatus
2026-08-17 10:10:00,P-101,3.2,62.1,18.4,Running
2026-08-17 10:20:00,P-101,4.8,66.7,19.2,Running
2026-08-17 10:28:00,P-101,7.6,73.5,21.8,Running
2026-08-17 10:35:00,P-101,12.4,85.2,25.7,Stopped
```

這段資料顯示：

- 振動逐步增加。
- 軸承溫度持續上升。
- 馬達電流同步提高。
- 最後設備停止運轉。

這類分析可以用於異常診斷、告警門檻調整、預防保養及預測維護。

## 7.3 比較標準製程曲線

將多個批次依照製程起點對齊後，可以比較：

- 升溫時間是否一致
- 保溫時間是否足夠
- 溫度及壓力是否落在標準範圍
- 攪拌轉速是否穩定
- 良品與待判定批次的曲線有何差異

比較製程曲線時，應先確認產品、配方、設備及製程階段是否具有可比性。

## 7.4 分析控制動作與反應延遲

時序資料可以分析輸入與輸出之間的時間關係，例如：

- 蒸汽閥開啟後，溫度多久開始上升？
- 增加冷卻水後，產品溫度多久下降？
- 調整燃空比後，煙氣含氧多久產生變化？
- 改變馬達頻率後，流量多久達到新的穩定值？

這些反應時間可用於控制參數調校、製程穩定性分析與設備效能評估。

## 7.5 計算時間型指標

時序資料可以形成許多與時間相關的指標：

- 超過上限的持續時間
- 低於下限的持續時間
- 設備運轉、待機及停機時間
- 從開機到達標的時間
- 升溫與降溫速率
- 一段期間內的波動幅度
- 尖峰需量出現的時間
- 能源與物料的區間累積用量

## 7.6 建立即時監控與預警

時序資料持續進入系統後，可以建立：

- 即時趨勢畫面
- 上下限告警
- 變化率告警
- 多測點組合條件
- 異常模式辨識
- 設備健康指標
- 預測模型與 Soft Sensor

交易資料主要保存已發生及已確認的事件；時序資料則能讓系統在過程進行中持續判斷目前狀態。

# 第八章　交易資料不可取代的應用

## 8.1 生產與工單管理

交易資料可以管理：

- 生產什麼產品
- 預計與實際生產數量
- 工單優先順序
- 開工、完工及工單狀態
- 工單與客戶訂單的關係

## 8.2 物料與庫存管理

庫存管理需要每一筆具有業務效力的入庫、出庫、領料、退料、調撥及盤點紀錄。儀表量測可以協助核對物料流動，但正式庫存仍需依照確認後的交易紀錄管理。

## 8.3 品質判定與放行

時序資料可以呈現檢驗前的製程條件，檢驗交易資料則保存：

- 檢驗項目
- 取樣時間
- 檢驗值
- 規格上下限
- 判定結果
- 檢驗及核准人員
- 放行或留置狀態

量測曲線可以支援品質原因分析，但正式品質判定仍是一筆需要追蹤與簽核的業務紀錄。

## 8.4 維修作業與責任追蹤

設備訊號可能顯示停機 90 分鐘；維修單則記錄報修、到場、檢查、更換零件、測試及完修等作業。

時序資料說明設備狀態如何改變，維修交易資料說明人員執行了哪些處置。兩者整合後，才能同時分析故障與維修成效。

## 8.5 成本、稽核與正式報表

成本結算與稽核需要明確的歸屬關係，例如工單、批次、部門、產品、會計期間及核准狀態。時序資料可以提供能源與設備使用依據，交易資料則提供正式歸屬與結算規則。

## 本章重點

> 時序資料適合解釋設備與製程的變化；交易資料適合管理業務事件、正式認定與作業責任。

# 第九章　把製造結果與製造過程連接起來

## 9.1 為什麼需要整合

單獨使用交易資料，可以知道哪一批合格、哪一批產量較低；單獨使用時序資料，可以知道溫度、壓力與能源如何變化。

將兩者連接後，問題可以進一步變成：

- 合格批次與待判定批次的溫度曲線有何差異？
- 哪一個產品的蒸汽單耗最高？
- 哪一台設備生產相同產品時較穩定？
- 異常壓力波動影響了哪些批次？
- 維修前後的振動與耗電是否改善？

## 9.2 批次與時間區間的連接方式

交易資料提供批次邊界：

```csv
BatchNo,Equipment,StartTime,EndTime,Product,OutputKg
B20260817001,R-101,2026-08-17 08:00:00,2026-08-17 11:00:00,Resin-A,950
```

分析系統便可以從時序資料擷取：

```text
Equipment = R-101
Timestamp >= 2026-08-17 08:00:00
Timestamp <  2026-08-17 11:00:00
```

接著計算該批次的製程特徵：

```csv
BatchNo,AverageTempC,MaximumPressureBar,OverLimitMinutes,SteamUsageKg,OutputKg
B20260817001,82.6,2.85,1,1280,950
```

## 9.3 交易資料提供業務上下文

時序測點 `R101_TEMP_PV` 本身只能表示 R-101 的溫度。經過交易資料連接後，這段溫度才會具有更多意義：

- 屬於哪一個批次
- 生產哪一種產品
- 使用哪一個配方
- 當時是哪一個製程階段
- 最終品質是否合格
- 實際產量是多少
- 操作班別及人員為何

這些資訊統稱為業務上下文。它把連續量測值轉換成可以依產品、批次、配方及品質進行比較的製造知識。

## 9.4 常見的連接鍵

| 連接方式 | 適用情境 |
|---|---|
| BatchNo | 批次製造、品質與配方分析 |
| WorkOrder | 工單績效、產量與能源分析 |
| Equipment＋時間區間 | 設備運轉、維修與停機分析 |
| Shift＋時間區間 | 班別產量、能源與操作比較 |
| MaterialLot | 原料批號與品質追溯 |
| EventFrame／製程階段 | 開機、升溫、反應、保溫、冷卻等階段分析 |

## 9.5 整合後的能源單耗案例

時序資料計算批次蒸汽用量：

```csv
BatchNo,SteamUsageKg
B20260817001,1280
B20260817002,1610
B20260817003,1425
```

交易資料提供產品與產量：

```csv
BatchNo,Product,OutputKg
B20260817001,Resin-A,950
B20260817002,Resin-B,1135
B20260817003,Resin-A,936
```

整合後計算單耗：

```text
SteamSpecificConsumption = SteamUsageKg / OutputKg
```

```csv
BatchNo,Product,SteamUsageKg,OutputKg,SteamKgPerProductKg
B20260817001,Resin-A,1280,950,1.347
B20260817002,Resin-B,1610,1135,1.419
B20260817003,Resin-A,1425,936,1.522
```

這時才能比較同產品、不同批次或不同設備的能源效率。

# 第十章　設備維護案例：故障如何形成、如何被處理

## 10.1 維修交易資料

```csv
MaintenanceNo,Equipment,ReportTime,RepairStart,RepairEnd,FailureReason,Action,Result
M20260817001,P-101,2026-08-17 10:35:00,2026-08-17 10:50:00,2026-08-17 12:20:00,BearingFailure,ReplaceBearing,Completed
```

這筆資料可以回答：

- 哪一台設備發生故障？
- 何時報修、開始維修及完成？
- 故障原因為何？
- 採取了什麼處置？
- 維修工作是否完成？

## 10.2 故障前的時序資料

```csv
Timestamp,Equipment,VibrationMMs,BearingTempC,MotorCurrentA
2026-08-17 10:10:00,P-101,3.2,62.1,18.4
2026-08-17 10:20:00,P-101,4.8,66.7,19.2
2026-08-17 10:28:00,P-101,7.6,73.5,21.8
2026-08-17 10:35:00,P-101,12.4,85.2,25.7
```

這份資料可以回答：

- 哪一個訊號最早開始改變？
- 異常發展了多久？
- 溫度、振動與電流是否同步變化？
- 是否可以設計更早的預警條件？

## 10.3 整合後的應用

將故障前後的時序資料與維修單連接，可以分析：

- 維修前的異常特徵
- 從出現前兆到停機的時間
- 維修後振動、溫度及電流是否恢復
- 相同故障是否重複發生
- 哪一種維修方式的改善效果較好

一句話總結：

> 維修單告訴我們「故障如何被處理」；時序資料告訴我們「故障如何形成」。

# 第十一章　時序資料品質

## 11.1 資料值之外的品質資訊

時序資料的可用性不只取決於是否有數值，也取決於量測與傳輸品質。

常見品質狀況包括：

- 感測器校正偏差
- 缺值或通訊中斷
- 重複資料
- 不合理跳點
- 數值長時間固定
- 設備與伺服器時間不同步
- 工程單位不一致
- 延遲上傳或離線補傳
- 人工補值或修正值

## 11.2 Quality 標記

```csv
Timestamp,Equipment,TagName,Value,Unit,Quality
2026-08-17 08:00:00,R-101,Temperature,80.2,C,Good
2026-08-17 08:01:00,R-101,Temperature,80.4,C,Good
2026-08-17 08:02:00,R-101,Temperature,,C,Bad
2026-08-17 08:03:00,R-101,Temperature,80.6,C,Uncertain
```

常見標記意義：

- Good：資料可正常使用。
- Bad：資料無效或未取得。
- Uncertain：資料存在但可靠程度需要進一步確認。

不同系統可能使用不同品質代碼，分析時應保留並解讀原始品質資訊。

## 11.3 顯示位數、解析度與準確度

數值顯示為 `80.1234°C`，只代表系統保存或呈現了四位小數，不代表感測器必然具有相同的量測準確度。

評估量測資料時，可以分別確認：

- 顯示位數：畫面呈現多少小數位。
- 解析度：儀器可辨識的最小變化。
- 準確度：量測值與真實值的接近程度。
- 校正狀態：儀表是否依規範校正。
- 採樣頻率：多久取得一次數值。

## 11.4 缺值與插值

當某個時間點沒有原始資料時，可以依使用目的選擇：

- 保留缺值
- 使用前一筆值
- 使用下一筆值
- 線性插值
- 使用區間平均值
- 依設備狀態或製程規則補值

插值是依規則估算的結果，不是儀表在該時間點實際量測的原始值。教材或報表應清楚標示原始值、彙總值與估算值。

# 第十二章　如何設計一個正確的資料問題

## 12.1 從「我要資料」轉成可執行問題

一個完整的製造資料問題可以依序確認：

1. 想觀察哪一個對象？
2. 想了解哪一項指標或事件？
3. 分析時間範圍為何？
4. 需要原始過程還是統計結果？
5. 需要哪一種資料粒度？
6. 結果要依什麼維度比較？
7. 哪一套系統保存正式認定值？

## 12.2 問題改寫範例

較寬泛的題目：

> 我要看工廠的溫度資料。

轉換成可執行題目：

> 顯示 R-101 反應槽最近 8 小時的溫度趨勢，以每分鐘平均值呈現，並保留每分鐘最大值以觀察瞬間高溫。

較寬泛的題目：

> 我要知道哪一批最耗能源。

轉換成可執行題目：

> 比較 Resin-A 各生產批次的蒸汽用量，依批次開始與結束時間計算區間用量，再除以合格成品入庫重量，得到每公斤產品蒸汽單耗。

## 12.3 設計報表前的確認清單

- 分析的是設備、工單、批次、產品還是班別？
- 時間區間如何定義？
- 班別跨日如何計算？
- 數值是原始值、平均值、最大值還是累積量？
- 正式產量採用生產確認值或入庫值？
- 缺值、壞值及補傳資料如何處理？
- 不同設備的單位與測點定義是否一致？
- 報表更新後，歷史數字是否允許重新計算？

# 第十四章　綜合案例：從一批待判定產品追查原因

## 14.1 問題情境

B20260817003 批次生產 Resin-A，最終產量為 936 kg，品質狀態為 Hold。分析人員希望了解這一批與正常批次有何差異。

## 14.2 第一步：由交易資料確認比較條件

```csv
BatchNo,Product,Equipment,StartTime,EndTime,OutputKg,Result
B20260817001,Resin-A,R-101,2026-08-17 08:00:00,2026-08-17 11:00:00,950,Pass
B20260817003,Resin-A,R-101,2026-08-17 13:20:00,2026-08-17 16:35:00,936,Hold
```

兩批產品及設備相同，適合進一步比較製程過程。

## 14.3 第二步：依批次時間擷取時序資料

擷取兩個批次期間的：

- 反應溫度
- 反應壓力
- 攪拌轉速
- 蒸汽閥開度
- 蒸汽累積用量

## 14.4 第三步：產生批次特徵

```csv
BatchNo,HeatUpMinutes,AverageHoldTempC,TempStdDevC,MaxPressureBar,SteamUsageKg
B20260817001,42,82.6,0.7,2.85,1280
B20260817003,55,81.4,2.3,3.08,1425
```

## 14.5 第四步：形成分析觀察

從資料可以觀察到：

- B20260817003 升溫時間較長。
- 保溫階段平均溫度較低。
- 溫度標準差較高，代表過程波動較大。
- 最大壓力較高。
- 蒸汽用量較多，但產量較低。

以上結果指出值得進一步檢查的製程差異。後續仍應結合配方、原料批號、設備狀態、操作紀錄及檢驗結果進行工程判斷。

## 14.6 案例結論

交易資料先找出需要分析的批次、產品、結果及時間邊界；時序資料再還原過程並比較差異。兩者共同建立由結果回到過程的追查路徑。

# 第十五章　課程總結

## 15.1 四個核心觀念

> 交易資料告訴我們「完成了什麼」。

> 時序資料告訴我們「過程如何發生」。

> 統計資料告訴我們「依某種規則摘要後得到什麼」。

> 將三者正確連接，才能解釋製造結果、追查問題並持續改善製程。

## 15.2 資料價值的層次

1. **記錄**：保存業務事件與設備量測。
2. **看見**：以報表及趨勢呈現現況。
3. **理解**：連接製造結果與製造過程。
4. **判斷**：找出差異、異常及可能影響因素。
5. **改善**：調整操作、維護、能源及製程策略。
6. **預測**：建立預警、預測維護與品質估測模型。

## 15.3 最後的判斷方法

面對一個新的資料需求時，可以先問：

- 想知道的是一件已確認的業務事件，還是一段持續變化的過程？
- 問題需要工單、批次、物料、檢驗或庫存等業務上下文嗎？
- 問題需要觀察趨勢、波動、持續時間或反應延遲嗎？
- 結果需要原始值、統計值，還是正式認定值？
- 兩種資料是否需要透過設備、批次及時間區間連接？

能夠回答這些問題，就能為不同的製造情境選擇合適的資料與分析方法。

# 附錄 A　課程開場文案

工廠每天都在產生資料。有些資料來自工單、領料、檢驗與入庫作業；有些資料則來自設備、儀表與控制系統。

這些資料都與生產有關，但觀察的角度不同。一張生產紀錄可以告訴我們完成了哪一批產品；一段溫度曲線則可以告訴我們這批產品在反應過程中經歷了什麼變化。

今天的課程將從同一批化工產品出發，認識交易資料、時序資料與統計資料，並了解如何讓它們互相連接。課程的目的不是選擇其中一種資料，而是理解每一種資料適合回答什麼問題，以及它們如何共同形成更完整的製造資訊。

# 附錄 B　課程結尾文案

完成今天的課程後，我們可以用兩個角度重新閱讀工廠資料。

第一個角度是結果：完成了哪一張工單、用了多少物料、產出多少成品、品質是否合格。這些資訊讓工廠能夠管理、追蹤與結算。

第二個角度是過程：設備如何運轉、溫度如何改變、壓力何時波動、能源在哪個階段被使用。這些資訊讓工廠能夠監控、診斷與改善。

當結果與過程透過工單、批次、設備及時間正確連接後，資料便不只是被保存，而是能夠用來解釋問題、比較差異、建立預警，並支持持續改善。
