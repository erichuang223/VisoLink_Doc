GOVERNANCE PRINCIPLES

所有管理決策都應回答四個問題

人

誰

是個人、群組、角色，還是系統整合身分？

域

能碰什麼

圖面、資料來源、資料夾或管理能力的範圍為何？

權

可以做什麼

只能瀏覽、可編輯、可管理，或具有最高管理責任？

證

如何證明

誰核准、何時生效、如何驗證、能否追溯與回復？

授權不是一次性設定；人員、任務與資料範圍改變時，權限也必須跟著被重新檢視。

OPERATING CYCLE

治理工作形成持續循環

1申請目的、範圍與期限
2審核責任人與風險
3配置身分、群組與權限
4驗證以實際角色測試
5監看狀態、稽核與異常
6回收調職、到期與離職
管理完成的定義：設定已儲存、實際角色已驗證、變更已有紀錄，而且到期或不再需要時有明確回收方式。

GROUP DESIGN

群組以「責任範圍」設計，比以人名設計更穩定

依組織

例如廠區、產線、班別或部門，適合穩定的責任邊界。

依任務

例如能源監看、品質分析或專案建置，適合跨單位合作。

依期間

例如承攬商或臨時專案，必須設定到期與定期檢視。

名稱看得出範圍與用途。
說明記錄擁有者與適用規則。
成員只保留仍有業務需要的人員。

停用群組後，其成員不再取得該群組授予的權限；停用前仍須盤點實際影響。

ROLE DESIGN

角色描述平台職責，群組描述資源範圍

角色適合管理

  • 一般監看、Studio 設計、系統管理等職責
  • 跨多個資源但能力一致的工作模式
  • 需要由治理規則統一控管的管理能力

群組適合管理

  • 特定廠區、產線、專案或資料範圍
  • 會隨組織與任務調整的成員集合
  • 同一批人共同需要的資源授權
設計口訣先決定「負責什麼」的群組，再決定「能做什麼」的角色，最後才處理必要的個人例外。

ACCESS LEVELS

Display 與 Folder 的四個權限層級

Viewer開啟並檢視 Display；Folder 為檢視此 Folder、子 Folder 及其中的 Display。
Editor包含 Viewer，可編輯 Display 內容；Folder 可建立 Display 與子 Folder，但不可重新命名、移動或刪除此 Folder。
Manager包含 Editor，可複製、重新命名、移動及刪除；移動的目的 Folder 仍需 Editor 以上。
Administrator包含 Manager，可設定權限及重新指派擁有者。
Folder 向下套用Folder 權限影響所有子 Folder 與 Display；調整上層前先確認使用者範圍。
全域公開Display 的獨立切換，以公開方式提供讀取；確認範圍後再操作。

權限層級越高，代表的不只是能做更多操作，也代表更高的變更與誤用風險。

EFFECTIVE PERMISSIONS

有效權限預覽：一次看到「這個帳號實際能用哪些東西」

  1. 開啟使用者清單該列「檢視權限」；唯讀，不改設定。
  2. Display／Folder可開啟的 Display、權限名稱與繼承結果；「顯示全部 Display」可比對沒權限的。
  3. DataBinding搜尋名稱、路徑、DataSource 或 View，看「是否可使用」。
  4. 系統功能Client、Display 瀏覽／編輯、DataBinding 使用、Admin 是否可用與判斷依據。
排查順序：Display 看得到，不代表每個 DataBinding 都能用；資料不出來時同時看 DataBinding 分頁。即時資料的使用與寫入，另見 DataGateway 即時「權限預覽」（Course 05）。預覽之後仍建議以實際帳號登入抽查。
PERMISSION VERIFICATION

權限驗證必須使用代表性帳號與實際操作路徑

1準備測試帳號一般監看或設計角色
2檢查導覽只看得到允許的範圍
3開啟 Display圖面權限正確
4驗證資料即時與歷史均可讀
5測試禁止項目不應使用的能力確實被擋下
驗證不是只測成功：還要證明使用者看不到不屬於自己的圖面、資料與管理功能。

GRAPHICS LIBRARY

圖庫管理：維護所有使用者在 Studio 看到的同一份圖庫

  1. 圖庫與分類新增、排序；同一張圖可屬多個分類，或用「引用分類」。
  2. 上傳 SVG不超過 1 MB、需有 viewBox；指令碼與外部連結會被自動移除。
  3. 接合點智慧圖形自動接上設備管口的位置；修改自動儲存。
  4. 製作智慧圖形參數、節點與線段、零件、控制點、接合點；至少一個零件才能儲存。

刪除圖形會從所有分類移除，已使用它的畫面會顯示空圖；刪除前先確認使用情況。

CLIENT SETTINGS

Client 設定：所有 VL Client 共用的班別條件與清單背景

  1. 新增條件名稱、開始與結束表示式，例如早班 t+6h 到 t+14h、夜班 y+22h 到 t+6h；最多 12 條。
  2. 表示式* 現在、t 今天 00:00、y 昨天 00:00，搭配 s m h d w mo y 加減。
  3. 儲存條件確認換算時間正確；Runtime 重新整理後生效。
  4. 清單背景JPG、PNG 或 WebP，最大 5 MB；「恢復預設」回到原圖。

使用者端的操作見 Course 01「班別一鍵切換」。背景圖存放在媒體庫並納入備份。

CACHE OPERATIONS

Cache 是 Runtime 查詢的承載與分流層

資料來源
正式資料仍由來源系統負責
→
Cache
保存可重用的查詢結果
Runtime ARuntime BRuntime C
  • 相同或相近查詢可重用結果，降低來源端重複負荷。
  • 多個 Cache 節點可以承接不同工作量，形成負荷分流。
  • Cache 不取代 DataSource，也不能掩蓋來源停止更新的問題。
  • 清除 Cache 會增加短期回源查詢，操作前必須評估影響。

CACHE HEALTH

用四組訊號判斷 Cache 是健康、吃緊或失去服務

連線與節點

健康狀態、節點角色、版本與連線延遲。

記憶體

已使用容量、限制與淘汰策略是否合理。

命中與操作

命中率、每秒操作量與 Runtime key 數量。

資料生命週期

永久、即將到期、歷史或孤兒資料的比例。

判讀原則單一數字沒有絕對好壞；要與平日基準、使用人數、查詢類型及異常時間一起比較。
TTL & SAFE CLEANUP

先控制生命週期，再考慮刪除 Cache

01

確認範圍

辨識近期、歷史、永久、孤兒或特定 DataBinding key。

02

評估影響

確認清理後哪些 Runtime 會重新向來源查詢，以及來源能否承受。

03

優先套用 TTL

透過到期策略逐步回收，避免一次清除造成尖峰。

04

最小範圍處理

只處理已確認的 key 或節點，不把全清當成標準排障步驟。

05

處理後觀察

追蹤命中率、記憶體、來源負荷與 Runtime 回應。

高風險動作：清除全部 Runtime Cache、移除節點或大幅縮短 TTL，應先有核准、維護窗口與回復方案。
LICENSE POINTS

授權以裝置點數計：1 點＝1 台登入中的裝置

  1. 怎麼計算同一帳號在兩台裝置登入占 2 點；Admin 與 DataGateway 登入不占點。
  2. 何時釋放心跳每 15 秒更新，超過 2 分鐘沒有回應自動登出並釋放點數。
  3. 強制登出點數不足時可強制登出某台裝置；先確認對方不在進行重要操作。
  4. 其他占點DataBinding 勾選 Redis runtime cache 會多用 1 點。
授權管理日常：授權總覽注意「即將到期」（30 天內）並提早續約；新增 License Key 每行一組；隔離網路用「離線啟用」（下載 .vlreq、匯入原廠回傳的 .vllic）。授權安裝識別碼不隨備份移動，還原到另一台 Server 後離線授權需重新申請。「使用歷史」的同時登入峰值可評估需要的點數。

適合回答

異常前後發生過哪些操作？特定變更是否成功？問題影響哪些資源？

不應取代

事件處理紀錄、變更單與業務原因仍要由負責人補充，不能只留下技術事件。

分享稽核畫面前，應遮蔽不必要的帳號、IP、查詢內容及其他敏感資訊。

OPERATION MODE

運作中／維護中：升級、搬移、大量資料作業前先切到維護中

  1. 切到維護中總覽「運作狀態」卡片 →「切到維護中」並確認。
  2. 暫停Runtime 查詢與即時資料、回寫、編輯 Display、所有設定修改。
  3. 仍可使用Admin 登入、查看狀態、切換總開關、備份與還原。
  4. 切回運作中Client 在 30 秒內自動回到原畫面，不需重新登入。

卡片記錄最後一次由誰在何時切換。勾選「同時允許讀取與切換運作狀態」的 Backup API Token，可讓備份中心在排程備份時自動切換。

BACKUP & RESTORE

備份成功只是第一步；可解密、可驗證、可還原才算可用

完整備份

適合重大變更、升級前與定期保護，涵蓋平台主要設定與資產。

快速設定備份

適合日常設定保護與較快的管理作業。

自訂資料備份

依需求選擇身分、設定、Cache、語系、資料來源、Display、媒體或稽核等範圍。

1建立選模式、範圍與加密密碼
2保存分離正式環境與備份位置
3檢查檔案有效、清單與版本可讀
4演練在受控環境執行還原
5驗證登入、權限、資料與 Runtime
RESTORE DECISION

還原是平台變更，不是單純把檔案放回去

還原前

  • 確認備份來源、建立時間與有效狀態
  • 確認完整或部分還原範圍
  • 選擇覆寫或只插入新資料的衝突策略
  • 通知受影響人員並安排維護窗口
  • 保留還原前自動或人工完整備份

還原後

  • 確認使用者、角色、群組與權限
  • 驗證 DataSource、View 與 DataBinding
  • 抽查 Display、媒體與多語系內容
  • 確認 Cache 與 Runtime 查詢恢復
  • 記錄結果、差異與後續處理
加密密碼遺失：備份可能無法還原；密碼必須由受控方式保存，且不可與備份檔放在同一個不受保護的位置。

單一系統每日自動備份

多套系統統一管理

連接備份中心
